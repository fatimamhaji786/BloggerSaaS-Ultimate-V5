15. First-Change Safety Rule

V5.1.14 implementation changes must be incremental.

The first functional change must:

1. Have a clearly defined purpose.
2. Identify the exact file being modified.
3. Preserve the V5.1.13 production architecture.
4. Avoid unnecessary refactoring.
5. Avoid unrelated changes.
6. Avoid secret/configuration exposure.
7. Be statically validated.
8. Be tested before the next functional change.
9. Record any regression.
10. Preserve the "LIVE_GATEWAY_OK" acceptance criterion.
